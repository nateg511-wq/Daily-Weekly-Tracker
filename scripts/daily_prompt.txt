Read CLAUDE.md in this directory top to bottom — it is the authoritative, self-contained runbook for this project. Do not rely on any memory of past sessions.

Run today's DAILY cycle exactly as CLAUDE.md's "update cycle" section describes, using the "light" path:

1. Quant refresh: `./.venv/Scripts/python.exe run.py quant` then `./.venv/Scripts/python.exe run.py numbers`.
2. Check each qualitative pillar's trigger table and the "What Changed" section of its report for anything that has fired since the currently active score set (see `active_qual_set` in config/scores.json). Do real web research per the Research Discipline rules (primary sources first, date every fact, label single-source claims, never blend market-price odds with institutional estimates).
3. If something material fired and clears the sufficiency rule (a single-source claim alone may never move a P): add a new dated draft score set in config/scores.json (key format YYYY-MM-DD_draft, or _draft2/_draft3 if today's key already exists from an earlier run today), move P only as far as evidence moved, write the one-line-per-window rationale, set active_qual_set to it. If nothing material fired, do NOT touch scores.json — leave the active set as-is.
4. Blend: `./.venv/Scripts/python.exe run.py blend`.
5. If you changed scores.json: update the affected report(s) content (keep the existing HTML/CSS templates untouched), update every date stamp and figure per the "Field checklist per report" in CLAUDE.md, render (`run.py render`), run `run.py selfcheck`, verify per the Verification list (recompute a couple of signals by hand, recheck facts, cross-check repeated figures, check PDFs for rendering breakage), then archive (`run.py archive`).
6. Commit your changes to git with a clear commit message describing what changed and why (or "no material change" if nothing moved). Never edit or rename any existing (non-today) score set, and never set any set's "status" to "committed" or add "stamped_by" — that stamp is owner-only, always leave new sets as "status": "draft".
7. End by printing a short summary: today's date, whether anything moved, the current THE FINAL NUMBER, and what (if anything) needs the owner's (Alex's) attention before the next stamp.

If you have no working internet/web research capability in this environment, do not invent a score change — just run the quant refresh, commit if anything changed, and say so plainly in your summary.
